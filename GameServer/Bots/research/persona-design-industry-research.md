# 人设设计行业调研:从"剧本卡"到"性格种子"(2026-10-09)

> **触发**:用户对人设 v1.0 的批评——"说话太具体(例句=模板)、追求太详细(框死想象力),应该让它自行探索,追求自己找;人设=性格+追求萌芽+与环境/他人互动;我想看他们的变化,人就是会变的。"
> **方法**:回到 Generative Agents **源码真身**(非论文转述)、AI Town 角色定义、SOTOPIA 心理计量式角色、Concordia 指令式,对比它们"给了什么/没给什么/什么会变"。

---

## 一、四家真身对比

### 1. Generative Agents(scratch.json 源码原文,非论文转述)

```json
{
  "name": "Isabella Rodriguez",
  "age": 34,
  "innate":    "friendly, outgoing, hospitable",        ← 天生性格:3 个形容词,就这么多
  "learned":   "Isabella Rodriguez is a cafe owner of Hobbs Cafe who loves to
               make people feel welcome..."              ← 自我概念:一小段自然叙述
  "currently": "Isabella Rodriguez is planning on having a Valentine's Day party
               at Hobbs Cafe ... from 5pm to 7pm."       ← 当前惦记:有时效的临时动机
  "lifestyle": "...goes to bed around 11pm...",          ← (作息,我们不抄)
  "daily_req": []                                        ← 每日硬性要求:空!
}
```

**关键观察**:
- **innate 只有 3 个词**——不是 3 段话。性格=底色,不是剧本
- **没有预设"人生追求"**。Isabella 的"追求"(情人节派对)住在 `currently` 里——**有明确时效、由事件催生、过期翻篇**。派对办完了,论文里她的 currently 就换成别的了
- **没有一句例句台词**。她的说话方式完全从 innate(friendly/outgoing)+场景里长出来
- **什么会变**:daily plan 每天重排、currently 随事件改写、learned 偶尔更新;**innate 永不变**

### 2. AI Town(简化版 GA)

角色 = `identity`(一段自然语言自我描述,≈100 词)+ 3 条初始记忆。同样:无例句、无预设目标,行为靠"每秒一个 tick 的记忆检索+对话决策"长出来。

### 3. SOTOPIA(心理计量式,最结构化)

角色 profile = Big Five 人格 + 道德价值 + Schwartz 个人价值 + 决策风格 + **secret** + 公开信息;社交目标按场景单独注入(不是常驻人设)。**心理学量表当骨架,追求场景化**。

### 4. Concordia(指令式)

角色 = instructions(一段"你是谁"的指导)+ 可选 goal component。追求是**组件**,按实验装配——框架层面就不把追求焊死在人设里。

## 二、行业共识(对我们最重要的一条)

| 层 | 内容 | 稳定性 | 出处一致性 |
|---|---|---|---|
| **性格底色** | 3-5 个特质词(GA)/Big Five(SOTOPIA) | **终身稳定** | 四家一致;心理学背书:成年人人格特质确实稳定 |
| **自我概念** | "我是谁"的短叙述 | 缓慢演化(经历改写) | GA learned / AI Town identity |
| **当前惦记** | 时效性动机/筹划 | **高频变化,事件驱动** | GA currently——这正是"追求"的正确形态 |
| **记忆/关系/目标** | 全部 | 持续演化 | 四家一致 |

**"人是会变的"的准确含义**:变的是**惦记什么、相信什么、和谁亲、想要什么**;不变的是性格底色。Isabella 三个月后还是 friendly/outgoing,但她惦记的早不是那场派对。**用户想看的变化,应该住在 currently 层,不该通过改性格来实现**——性格翻转反而假(人格心理学:成年人 Big Five 十年级别才漂移)。

## 三、对我们 v1.0 人设卡的自检(认错)

| v1.0 的问题 | 违反的原则 |
|---|---|
| 说话给了例句("砍。""追。") | GA 无例句;例句=让模型复读,恰是"模板机械化"的来源 |
| 追求写成终身目标("等级榜第一+裁决之杖") | 追求应在 currently 层有时效;终身目标=剧本 |
| 身份写成职业标签("练摊商人""独行刺客") | 这是**行为预测**不是性格;商人味应从"惜财+江湖气"的特质里长出来 |
| 红缨"青铜→裁决路线图" | 还违反服务器事实(裁决=战士武器,红缨是龙枪)——写死的目标连数据都错了 |

## 四、结论:三层种子式人设(采纳进 v1.1)

```
人设 = 性格种子(3-5 个词,终身不变)      ← GA innate 式
     + 身份底色(一句话,自我概念起点)     ← GA learned 浓缩
     + 当前惦记(1-2 句,有起点时效)      ← GA currently 式:过期自动退场,由经历更新
说话风格 = 性格种子的一部分(如"话少""浮夸"),绝不给例句
追求     = 不预写。由 [抬头触发器×性格种子×经历] 涌现,登记进 Goals(已有工具),完成/放弃/过期自然流转
演化     = 当前惦记随反思/大事改写(Memory 里加 scratch 区);自我概念偶尔重写;性格永不变
```

**变化可见性**(用户要的"我想看他们的变化"):_colony.md 增加"当前惦记"列——它是人设里唯一高频变动的层,一周后 12 个人的惦记应该长得完全不同,且每条都能追溯到某次经历。这就是变化的展览窗。

## 五、语言层修正(GPT 评审第一条,一并采纳)

保留 2003 网吧传奇语感(CommonPromptHead 已有,不动);人设卡**不再单独写说话风格例句**,说话由"性格种子+文化头"共同生成。规则 16 采用 GPT 版本:长期活跃的玩家角色,主要生活发生在游戏活动里,不编造上下线/现实生活事件,可以休息挂机但始终存在于世界。
