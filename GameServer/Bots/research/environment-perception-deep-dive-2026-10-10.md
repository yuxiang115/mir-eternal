## 一、四案例的核心事实(源码/文档级)

### 1. NVIDIA × KRAFTON PUBG Ally(技术博客全文)

- **System1/System2 分工**:行为树(移动/瞄准/即时战斗,tick 级)+ SLM(意图理解/协作/语音)。**边界划分本身是工程重心**——我们同构(反射层/LLM 层)✓
- **观察工具设计**:一组工具各返回"引擎权威数据切片的纯文本视图"("M416,24/30发,HP78%,安全区内")。SLM 事件驱动触发后 **"observes what it needs"——按需拉取,不全量注入**
- **静态/动态分离(最关键)**:确定性游戏规范(地图/武器/规则)进 system+知识查询工具;**实时状态必须工具重查**——且 prompt 明确约定"工具结果是本局唯一事实来源";蒸馏时教师示范"通过工具重新观察而非回忆前几轮"的习惯
- **缓存**:稳定指令+游戏上下文跨轮一致,每轮只更新最相关的实时信息——**和我们 prefix cache 架构同构** ✓

### 2. agent-wow(仓库克隆+实战报告)

架构:Agent ↔ JSON-RPC(仅 session.logout 内置) ↔ WoW 客户端 ↔ 服务器;游戏机制走 Docker 模块(gRPC 订阅原始封包)。

**40 分钟完成兽人新手区的四个支柱**(报告原文核实):
1. **SQL 数据挖掘**:直接从 db_world 挖任务需求/发布 NPC/刷怪坐标 → 生成任务清单+位置规划(作者类比"查 Wowhead 攻略")
2. **自写 C++ 寻路程序**:读 mmaps 导航网格 → Detour 寻路 → JSON 航点 → 逐点发移动包;**找不到路会报错**(不是默默放弃)
3. **订阅 27 种 SMSG 封包**做世界感知(任务对话/升级/拾取/**CAST_FAILED/NOTINRANGE/BAD_FACING/TRAINER_BUY_FAILED 等失败反馈**)
4. **行为循环**:poll 封包→更新世界模型→规划→执行→用错误封包验证

**作者披露的失败与局限**(重要):agent 没按预期封装高层 RPC,只在封包层干活;作者自己此前 1.6 万行无头客户端代码败给"buggy movement + janky pathfinding";无沙箱;穿墙 bug。

### 3. MP5(仓库克隆:Percipient/Patroller 源码+prompt 原文)

- **主动感知 prompt 原文**:"主动向 Perceptor 提出你最感兴趣/最需要的问题";环境信息**只有问了才有**(block/creature/biome/bright/datetime/weather 分类);三条判据——**不匹配→立刻停止并说理由 / 部分匹配→继续问最需要的问题 / 足够判断→立刻停止并说依据**
- **Patroller(执行前检查)**:每个动作有 `check_action_preparation`——mine 需要 tool、craft 需要逐材料核对数量,缺什么返回带原因的 feedback。**这是"动作开始前的条件审计",我们的工具回执只有"执行后"的**
- 感知问题是**围绕当前任务生成的**(不是随机好奇),由 task_information 驱动

### 4. Voyager(此前已深读):自动课程+技能库+环境反馈迭代;它的观察是全量 API 注入(比我们弱,不参考其感知)

## 三、新发现(GPT 没说的)

### N1|agent-wow 的成功与我们的人设有张力
agent-wow 拿到的是**全量服务器数据**(SQL 任务库+导航网格),等于开了攻略网站+透视。它能自主是因为信息充分。但我们 v1.3 定了知识边界(亲历/传闻/推测)——**按 agent-wow 的路子走会毁掉"12 个不同经历的玩家"**。折中方案:**导航可达性是系统级事实(plan_route 对所有人开放,像地图软件);怪在哪/掉什么是角色级知识(守边界)**。真人也是这样:人人会看地图,不是人人知道沃玛爆什么。

### N2|失败反馈是 agent-wow 感知的核心,不是成功反馈
它订阅的 27 种封包里最值钱的是 **CAST_FAILED/NOTINRANGE/BAD_FACING/BUY_FAILED**——每个失败都带原因。我们的工具回执是"已喊话/正在前往"式的乐观承诺,失败原因(agent-wow 式)只在挪窝连环失败才出现。**红缨不知道稻草人过不过得去,是因为我们的导航从不回答这个问题,不是因为模型怂。**

### N3|MP5 的"执行前条件审计"填 G0 活动卡的另一半
Patroller 的 check_action_preparation(动作开始前逐条件核对,缺什么带原因拒绝)正是我们 G0 活动卡缺的执行侧:现在只在完成后检查"金币>=N",**发起时不检查**(药够不够/等级够不够/路线通不通)。两段式回执=开始回执(MP5前审)+结果回执(agent-wow后验)。

### N4|PUBG Ally 的蒸馏习惯我们可用 prompt 近似
"工具结果是唯一事实来源,重新观察而非回忆"——这句可以直接写进我们的规则 15,成本低。
