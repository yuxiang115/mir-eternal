# 《传奇永恒》真玩家闭环系统设计(v1.0,供 GPT+用户讨论)

> **版本**:v1.0 — 2026-10-09 深夜
> **决策记录(用户拍板,存档)**:作息/上下线系统(v1.3)冻结搁置。理由:**人有作息是人的限制,agent 不应该模仿人类的限制**;进游戏要看到所有人都在、都在忙;沉浸感 > 峰谷电费。v1.3 文档保留不删(附 shelved 标记),其中的工程件(SessionEpoch/事件驱动反思/AFK 唤醒预算)按需回收。
> **新北极星**:12 个有自主意识的玩家,把《传奇永恒》**真正玩起来**——形成打宝、升级、竞争、合作、经济交易、人际关系的自运转闭环。不是挂机机器人,不是模拟人生村民。

## 一、Agent 回路哲学(参考 openclaw / coding-agent harness)

游戏 agent 和编码 agent 是同一个道理,harness 的四件事我们对应如下:

| harness 组件 | 编码 agent | 我们 | 现状 |
|---|---|---|---|
| 工具循环 | 读文件/改代码/跑命令 | 26 个游戏工具 | ✓ 已合规(tool_calls+回执) |
| 世界反馈 | 编译报错/测试结果 | 战斗结果/购买成功失败/NPC 应答 | 🟡 部分(战斗有日志无回执语义) |
| 记忆 | CLAUDE.md/笔记 | BotMemory 分层 + remember | ✓ 已有 |
| 计划/反思 | todo/plan 模式 | DailyPlan/goals/commitments/反思 | ✓ 已有(反思待改事件驱动) |

**缺的不是回路,是回路上挂的游戏内容**。工具目录里没有"传奇的灵魂操作"(NPC 对话/任务/交易/行会/PK/好友),agent 再聪明也只能砍羊——这就是"挂机机器人感"的真正来源。

## 二、人设与 Prompt 修正(破除"下线"心智模型)

### 问题定位
现有人设卡带"作息"字段("工作日晚9-11点")+现实职业背景(公司主管/职场新人),模型据此自然演出了"下班了/写作业了/吃饭去了 5555"——作息系统虽搁置,**人设里的现实生活坐标必须清掉**,否则假下线继续发生。

### 修正原则
1. **身份移到游戏内**:不写现实职业,写"他在传奇世界里的身份"(散人猛男/练摊商人/大姐头/独行刺客)
2. **删"作息"字段**,换"追求/忌惮/消费观"等游戏向维度
3. Prompt 规则加一条(16):"你是这个世界的常住者,没有'下线/回家'的概念;累了就挂机打怪,缺什么就去赚,想谁了就去找"

## 四、工具扩展(26 → 40,三层)

### G1 层:游戏内核(最高优先)
| 新工具 | 包装 | 回执要点 |
|---|---|---|
| `npc_talk(npc, 选项)` | 走到 NPC→对话树步进 | 返回当前对话页+可选项(任务/商店/传送),agent 自己选 |
| `quest_accept / quest_complete` | 对话树中的任务节点 | 真实接单/交单,进度进观察 [任务] |
| `sell_item(名, 数量)` | 寻路开店 NPC→开店→出售 | 回执价格与背包余量;**经济从"只进不出"变活** |
| `attack_player(名)` | 指定玩家为攻击目标 | 回执含 PK 值变化警示("杀了会红名");PK 是毒玫瑰×夜色无声约战的执行件 |
| `add_friend / remove_friend` | 好友列表 API | 好友在线状态进观察 [好友] |

### G2 层:经济与社群
| 新工具 | 包装 |
|---|---|
| `setup_stall(物品列表,价格) / close_stall / browse_stall(玩家)` | 摆摊三件套——纵横四海的练摊人设落地,buy_from_stall 让 bot 间形成真实市场 |
| `guild_create / guild_invite / guild_join / guild_leave / guild_info` | 行会五件套(结盟/敌对 G4);乱世佳人"建行会"追求的执行件 |
| `send_mail(玩家, 内容) / check_mail` | 邮件系统包装;**[信箱] 成为 agent 接收系统信息/离线消息的通道** |

### G3 层:认知增强(不是工具,是机制)
- **世界反馈语义化**:attack/grind/use_skill 回执附结果解释("打了 3 刀它不掉血——防高,换技能或换怪");失败要有"为什么"
- **打听机制**(纯 prompt 侧):被问"X 哪里打"的 bot 翻自己 Knowledge 回答——**点对点知识传播**,没有的就说不知道(知识边界)
- **亲历掉落统计**(服务器自动):击杀→掉落按怪型累计进 Knowledge("钉耙猫:杀 120 只,药 3 次,匕首 1 把")——打宝情报从亲历长出来

## 五、六大闭环怎么闭上

| 闭环 | 现状 | 闭上靠 |
|---|---|---|
| 升级 | ✓ 强(挂机/追击/学技能已修) | + NPC 任务经验并入;攻略→换图(已有 check_guide/goto_map) |
| 打宝 | 🟡 只会捡,不懂"哪出什么" | + 掉落统计 + 打听 + 知识边界("毒玫瑰听谁说沃玛出裁决,自己没去过") |
| 竞争 | 🟡 只会嘴上约战 | + attack_player + PK 值 + 约战承诺(make_plan 已有)→ 真打 |
| 合作 | 🟡 组队已闭环 | + 好友(稳定的合作网)+ 行会(组织化)+ 红缨带精灵之吻出师 |
| 经济 | 🔴 只买不卖 | + sell_item + 摆摊 + 交易 → 纵横四海收货喊卖、白娘子卖药、买家比价 |
| 人际 | 🟡 关系/人情已有 | + 好友/行会做载体 + 邮件传话 + 爱恨情仇有事件可挂(PK 结仇、救命结义) |

## 六、自主意识强化:从挂机机器人到"抬头看路"

AutoGrind 仍是身体,但 agent 需要周期性自问"这么打对吗":

1. **抬头触发器**(程序侧信号,提示 agent 重新评估):升级速度低于攻略预期 / 连续死亡 / 金币买不起下阶段刚需 / 等级解锁新图新技能 / 约战临近 → 观察注入"[该抬头了] 你已经 3 小时没升过级,查攻略/换图/买装备/找人带,自己选"
2. **失败→策略改变**:死亡反思已有;扩展 grind 无进展/打不动 → 不是重试而是换法(反思工具箱:换怪/换图/换技能/组队/买装备)
3. **计划复盘**:DailyPlan 已有;每次反思时对照(做了几件/为什么没做)
4. **动机冲突**(v1.3 遗产回收):承诺 vs 收益的取舍进观察,取舍结果写记忆

## 七、信箱与系统信息(agent 的"收件箱")

- MailData 包装成 check_mail/send_mail;系统邮件(补偿/公告/GM)投递进 [信箱]
- 观察 [信箱] 块:未读摘要(谁/何时/首行);重要信(约战/行会召集)触发唤醒
- 挂机/战斗中收到的私聊走既有 ChatMemory 队列 + 转换时摘要(v1.3 的 SocialInbox 简化版,无 Active/AFK 二分)

## 八、成本护栏(无作息系统之后)

已就位:缓存 94-98%、空转治理(无动作 0%)、观察 800 字截断、90% 压缩线。
**可选纯参数旋钮(无存在感、不碰世界)**:`PeakThinkIntervalMultiplier`——峰时思考间隔×2,全员照常在线打怪,只是想得省点。要不要开由用户定,默认关。

## 九、分期

- **G1 游戏内核**(先行):npc_talk/任务闭环 + sell_item + attack_player(PK) + 好友三件 + 新人设卡上线
- **G2 经济社群**:摆摊三件 + 行会五件 + 邮件/信箱
- **G3 认知深化**:事件驱动反思(研究项回收)+ 对话记忆化 + 掉落统计 + 打听/知识边界
- **G4 涌现**:社会网络种子(关系网初始条件)+ 约战/抢 BOSS 竞争事件 + 行会结盟敌对 + SOTOPIA 式盲评

**验收涌现场景**(G4 后应能观察到):纵横四海在村口摆摊卖匕首,水晶之恋来比价买走;乱世佳人建行会拉拢红缨赵子龙;毒玫瑰 10 级准时约战夜色无声,白娘子场边备药;魔法小王子打听火球书,从白娘子手里买到二手;赵子龙做 NPC 任务链换了装备——**没有一行剧情代码,全部从各自追求里长出来**。

## 十、给 GPT 的开放问题

1. 工具从 26 → 40:tool schema 在 system 前缀,一次性缓存重建可接受;但对决策质量的影响(选择过载)?要不要按场景分组注入(全量定义+分组描述)?
2. npc_talk 粒度:一步一选项(细控,轮次多)vs 宏命令"去找铁匠买 5 瓶红药"(省轮次,黑盒)——我倾向细粒度+常用链路宏包装并存,可以吗?
3. attack_player 的安全边界:PK 值/红名惩罚如何反馈才能让 agent 真的"掂量"(而不是无脑开红)?被杀的 bot 记仇的粒度?
4. 摆摊 bot 站桩期间是否给了"挂机感"回潮?(对策:摆摊时可聊天/吆喝/记账,观察保持活跃)
5. 掉落统计会不会把 bot 变成"数据库玩家"(满口概率)?对策:统计只进 Knowledge 供查询,不主动说数字。
