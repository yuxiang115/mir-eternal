## 一、Agent 回路:补上 GPT 指出的缺环

GPT 的判词准确:**回路四件套(工具/反馈/记忆/计划)都在,但没有"目标执行状态"——agent 发起行动后不知道进展到哪、何时算成、失败该换法**。这正是"挂机机器人感"的最后一块拼图。

### G0:活动执行状态(新增,最高优先)

每个"有意图的活动"(非闲聊)由 LLM 发起时附一张**活动卡**,程序持续追踪:

```json
{
  "activityId": "act-204",
  "goal": "攒 800 金买青铜剑",              // 为什么
  "action": "打钉耙猫卖药",                  // 在干什么
  "successCondition": "金币>=800 且背包有青铜剑",  // 怎样算成(服务器可验证)
  "status": "in_progress",                   // in_progress / done / failed / replanned
  "progress": {"金币": 214, "距目标": "586"},   // 相关量的真实变化
  "blocker": null                            // 为什么推不动(钱不够/路不通/等级不足)
}
```

**三条硬规则**:
1. **"动作开始"≠"任务完成"**(GPT 最重要的一条):工具回执全部改两段式——`goto_map` 返回 `in_progress(activityId)`;**到达/受阻/失败由后续游戏事件更新活动卡**,agent 下轮看到的是事实结果,不是工具的乐观承诺。attack_player"指令已接受"≠"造成伤害";quest_complete"已提交"≠"奖励已发放"
2. **失败必须换法,不是重试**:活动卡 status=failed 时,观察注入"[卡住了] 原因:X —— 继续硬打,还是换方法(换怪/换图/组队/攒钱/放弃)?"——换法选择记进记忆(Reflexion)
3. **进度入观察**:`[当前活动] 攒钱买青铜剑 — 金币 214/800,钉耙猫掉药稳定` ——挂机中的 agent 每次抬头都知道自己在干嘛、干到哪了

实现落点:BotBrain 新增 `CurrentActivity`(活动卡)+ 反射层/事件回写 progress;**不新建 Planning Agent,在现有意图执行器上增量**(GPT 建议)。

### 计划改名:DailyPlan → Plan

GPT 正确:无作息后计划不该绑自然日。"打到某件装备"跨三天,"送 5 瓶红药"五分钟。Plan 生命周期由目标与事件决定:完成/放弃/被更重要事件打断才翻篇,零点不清空。(实现上:`PlanDate` 字段改为 `PlanExpiresWhen` 可空)

## 二、人设:三层种子式(v1.1 重写)

调研结论(`persona-design-industry-research.md`):GA 源码的 `innate`(3 个形容词)/`learned`(一段)/`currently`(有时效的惦记)——**无例句、无终身追求**。人是会变的:变的是**惦记/信念/关系/目标**(currently 层高频变),不是性格底色(终身稳定,人格心理学背书)。

### 新结构

```
人设 = 性格种子(3-5 词,终身不变)
     + 身份底色(一句话自我概念起点)
     + 当前惦记(1-2 句,起点动机,自然过期)
说话风格 = 性格种子的自然结果(话少/浮夸/毒舌是词,不是例句);2003 语感由共享文化头承担
追求     = 不预写!由 [抬头触发器×性格×经历] 涌现,登记 Goals 自然流转
演化     = 当前惦记随反思/大事改写;自我概念偶尔重写;性格永不变
```

### 演化的展览窗

`_colony.md` 加"当前惦记"列——人设里唯一高频变动的层。**验收:一周后 12 个人的惦记应长得完全不同,且每条可追溯到某次经历**(毒玫瑰的惦记从"没人骑她头上"变成"10 级约战赢了之后想收徒"——这就是用户想看的变化)。

### 规则 16(采用 GPT 版本)

> 你是长期活跃在《传奇永恒》服务器中的玩家角色,有自己的游戏目标、经历、朋友、竞争对手和江湖恩怨。你的主要生活发生在游戏活动中:练级、打宝、交易、组队、探索、PK。不要主动编造不存在的上线、下线或现实生活事件。你可以休息、挂机或停止当前活动,但仍然存在于游戏世界。所有行动与取得的成果必须符合真实游戏状态。

## 三、服务器能力与工具(审计修正:v1.0 说 14 实为 18)

系统底座盘点不变(六系统全在,tool=包装)。**GPT 门槛采纳:每个系统先跑通一条真实闭环链路再批量开放**(尤其 1215 个任务,先用 1 个能从接取走到交奖的任务打通)。

| 层 | 工具(18 个) | 闭环验证门槛 |
|---|---|---|
| G1 | `npc_talk(npc,option)` `quest_accept` `quest_complete` `sell_item` `attack_player` `add_friend` `remove_friend` `friend_list` | 1 条任务全链路;开店→卖→金币背包实变;PK 判定→战斗→惩罚全真实 |
| G2 | `setup_stall` `close_stall` `browse_stall` `buy_from_stall` `guild_create` `guild_invite` `guild_join` `guild_leave` `send_mail` `check_mail` | 摆摊原子扣款;行会走真实邀请/接受;邮件投递→未读→已读 |

**接口纪律(GPT 全采纳)**:宏工具(quest_accept 等)必须走与真人一致的服务器校验,不绕过前置;需要寻路/交互距离的工具返回 in_progress 不谎报成功;PK 动手前回执附安全区/PK 模式/预期惩罚(让 agent 掂量),动手后由服务器事实通知结果;对真人的主动 PK 加独立策略边界(好战≠无休止骚扰)。

## 四、知识系统(从 G3 前移 G1,GPT 判定正确)

三级知识可信度,替换"共享全知攻略":

| 级 | 例子 | 机制 |
|---|---|---|
| **亲身** | "钉耙猫我杀了 120 只,掉过 3 次药 1 把匕首" | 掉落自动累计(区分**目击掉落**与**拾取到手**);去过哪张图、哪个 NPC 卖什么,自动记 |
| **传闻** | "红缨说村北铁匠有卖技能书" | 打听=whisper 问人;对方翻自己的亲身库回答;传闻带来源与时间,可能过时 |
| **推测** | "这怪等级高,兴许掉更好的" | agent 自己记的假设;验证后升级为亲身或删除 |

`check_guide` 权限化:只返回①本职业②本级段③与已遇内容相邻 的条目;**不向 agent 提供任何未经发现的全服数据**(掉落表/全地图信息不出现在任何工具里)。知识可按物品/怪物/地图/人物检索(记忆检索增强,不必新工具)。

## 五、社交后果闭环(GPT:难的不是工具是后果)

工具只让约战能打起来;爱恨情仇要靠**事件→认知→后续选择**的链路:

```
挑战 → 接受/拒绝 → 战斗(服务器事实) → 双方各记经历 → 认知变化(经性格中介) → 后续选择变化
```

- **事件不直接决定情绪**(GPT 关键原则):被杀≠自动记仇——毒玫瑰记仇苦练、白娘子可能原谅、血饮狂刀可能尊敬强者。性格种子就在这里起作用
- 关键社交事件自动形成认知素材(帮打 Boss=欠人情/多次拒组=不愿合作/PK 被杀=敌意或敬畏),认知写法由 agent 自己按性格定
- 跨事件关系记忆:约战结果影响下次是否应战/组队/交易(接 SocialHistory 六维,P1)

**信任分级**:邮件/聊天是玩家发言(可提议交易约战,不可当指令);系统事件才是系统级事实。防止真人用邮件文本诱导 bot 转账/丢装备。

## 六、反馈纪律(GPT 细节全采纳)

1. 服务器能确认的原因=事实("它 3 刀没掉血");其余标注推测("可能是防高,也可能是没命中——查攻略或换技能试试")
2. 观察按目标优先级呈现(800 字截断不能吃掉关键事实);NPC 选项/摊位库存/路径详情按需查询工具化
3. 人设追求用服务器数据校验(种子式天然免疫:不预写就不会写错职业装备)

## 七、分期(v1.1 按 GPT 重排:按可玩闭环,不按系统类别)

| 阶段 | 内容 | 必须能演示 |
|---|---|---|
| **G0 执行质量** | 活动卡/两段式回执/失败换法/Plan 改名 | **连续失败后自己换方法**;挂机中随时知道进度 |
| **G1 成长内核** | NPC 任务链(先打通 1 条)+ sell_item + 跨图 + 三级知识+掉落统计 | 一个角色自主完成任务→赚钱→买装备→学技能→继续升级(红缨演示链,GPT 场景) |
| **G2 打宝与学习** | 打听机制 + 知识传播 + 装备需求规划 | 不知道装备来源的角色自行调查→尝试→修正认知 |
| **G3 经济与社群** | 好友 + 邮件信箱 + 摆摊四件 + 行会五件 | 玩家间真实物品交换、组织合作与利益冲突 |
| **G4 竞争与恩怨** | attack_player/PK + 约战 + 抢怪 + 行会敌对 + 跨事件关系记忆 | 一次真实冲突影响之后的行为选择 |

**G1 验收演示(采用 GPT 的红缨链,零脚本)**:检查自身→发现可学技能→不知道书哪买→打听/查 NPC→发现缺钱→去合适的图打怪卖货(反射层执行,抬头评估)→攒够→买书→学习→验证技能表→更新打怪策略并写记忆。每一步都是她自己的选择,系统只提供可验证的任务/知识/工具/反馈。
