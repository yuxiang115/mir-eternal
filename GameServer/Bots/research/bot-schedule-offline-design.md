# Bot 作息与上下线系统设计(v1.1,供 GPT review)

> **版本**:v1.1 — 2026-10-09(v1.0 review 中用户指出:谷时覆盖率不足——原作息表 08:00-15:00 空场 7 小时,占工作日谷时 41%;v1.1 引入"在线三态",谷时全员在线)
> **作者**:ZCode;**评审**:GPT
> **配套背景**:`bot-architecture.md` v4.0(整体架构/运行原理/as-built)
> **一句话**:让 12 个 bot 像真实玩家一样有节奏——**谷价时全员在线(该挂机挂机),峰价时 80% 下线**,告别/回归有仪式感,记忆跨日连续。

---

## 1. 背景与动机

### 1.1 来自聊天日志的观察(2026-10-09 Chat.log)

bot 们**已经在自发表演上下线**,但都是假的:

```
17:41 水晶之恋: 偶再刷十来分钟就撤啦,家里要吃饭了5555
17:43 水晶之恋: 886各位~~~~偶下线写作业去啦,明天放学再来!
18:03 乱世佳人: 水晶妹妹咋又上来了,作业写完啦?哈哈   ← 假下线穿帮
18:03 水晶之恋: 哈哈还没呢姐,我妈喊我写作业了5555,明天放学老地方见!
```

模型自己长出了"预告下线→道别→给理由→约明天"的完整社交仪式(全部符合人设:学生号说写作业,上班族说开会),唯一缺的是**系统层的真下线**。这个功能是把已经存在的涌现行为接到真实机制上。

### 1.2 成本动机:DeepSeek 峰谷电价

DeepSeek API 工作日两个高峰窗口(价格 ×2):

| 口径 | 窗口 1 | 窗口 2 |
|---|---|---|
| UTC(官方) | 周一~五 01:00-04:00 | 周一~五 06:00-10:00 |
| 北京时间 | 09:00-12:00 | 14:00-18:00 |
| **美国中部·夏令时(服务器所在,CT)** | **前一日 20:00-23:00(晚间)** | **01:00-05:00(凌晨)** |
| 美国中部·冬令时 | 前一日 19:00-22:00 | 00:00-04:00 |

要点:
- 排除中国法定节假日(那天全天谷价);周六周日全天谷价
- 服务器在美中时区,有夏令时切换 → **峰时窗口必须存 UTC,按服务器时区动态换算**,不能写死本地时间
- 对用户体感:工作日晚上 8-11 点(陪玩黄金档)和凌晨 1-5 点(无人观看)是贵价时段

### 1.3 成本模型

设谷价=1、峰价=2,成本 ∝ 在线 bot 数 × 时间 × 价格:

| 方案 | 工作日晚间峰(3h)留守 | 凌晨峰(4h)留守 | 周成本(相对单位) | 节省 |
|---|---|---|---|---|
| 现状:12 人全天在线 | 12 | 12 | 2436 | — |
| 峰时留 3+1 人 | 3 | 1 | 1726 | **29%** |
| 峰时留 2+0 人 | 2 | 0 | 1656 | **32%** |

凌晨窗口无人观看,建议归零或只留 1 人;晚间窗口可能有真人玩家,留 2-3 人维持世界活性。综合目标 **80% 下线 ≈ 周省 30%**。

## 2. 目标与非目标

**目标**:
1. **谷时全员在线(v1.1 核心修正)**:便宜时段 12 人一个不少——人不在键盘前的用"挂机"覆盖(号在线自动打怪,人去上班/上学/睡觉),这正是 2003 网吧最真实的生态
2. 真实的上下线:下线=角色离开世界(真人可见"他掉了"),上线=重新出现并自然打招呼
3. 峰时 ≥80% 下线(成本硬闸,程序保证)
4. 作息由**人设**驱动:谁什么时候"在键盘前/挂机/下线"有性格原因,不是随机数
5. 仪式感:道别有理由(人设化)、回归有衔接(记得昨天)
6. 离线零 LLM 成本;挂机近零 LLM 成本(反射层免费);不伪造离线成长(遵守 GPT 二轮原则)

### 在线三态(v1.1 新增,取代 v1.0 的二值在线/离线)

| 态 | 角色 | LLM 成本 | 对应现实 |
|---|---|---|---|
| **Active 在键盘前** | 全功能:聊天/社交/决策/挂机都活 | 正常(谷价 1x) | 人坐在网吧 |
| **AFK 挂机中** | 号在线:反射层自动打怪/喝药/捡东西;思考间隔 ×4~6;不主动说话;私聊进 SocialInbox 排队 | ~1/5 | 人上班/上学/睡觉,号开着(2003 挂机外挂生态) |
| **Offline 下线** | Despawn 离开世界 | 0 | 下机回家 |

- 转换时机:**Active↔AFK 由人设作息表驱动**(上班/上学/睡觉时段=AFK);**Offline 只由峰时硬闸驱动**(谷时不强制任何人下线)
- AFK 呼应路线图 P0 的 FocusState/SocialInbox(Bounded Attention):挂机态=FocusState.AFK 的第一个落地场景;AFK 期间好友私聊不回复,回到键盘前统一处理("刚下班,看了消息")——比秒回更像真人
- 成本注:谷时全员在线但 AFK 占多数时,实际 LLM 消耗 ≈ 3-4 个 Active bot 的量;峰时行为与 v1.0 相同(29-32% 周省不变)

**非目标(本轮不做)**:
- 点卡/网费经济系统(bot 花金币买在线时长)→ P2 备选
- 离线留言信箱(真人私聊离线 bot 的消息存档)→ P2
- 跨 bot 相约次日时间的社会化协调(已有 make_plan,先让它自然工作)
- 下线后角色留"尸体位"在城里(直接 Despawn,与真人掉线表现一致)

## 3. 总体设计:三层控制

```
┌─────────────────────────────────────────────────────┐
│ 第1层 成本硬闸(程序,不可协商)                        │
│  · 峰时日历(UTC窗口×服务器时区×节假日表)              │
│  · 峰时在线配额:晚间≤3人,凌晨≤1人(可配)              │
│  · 超额→按夜猫分强制下线,无视人设                     │
├─────────────────────────────────────────────────────┤
│ 第2层 人设作息(程序执行,人设定义)                     │
│  · PersonaCard.作息 = 每周在线窗口表(服务器本地时间)   │
│  · 窗口边界±15分钟随机浮动(去机械化)                  │
│  · 人设窗口与峰时冲突→人设让路,给角色编台阶下           │
├─────────────────────────────────────────────────────┤
│ 第3层 LLM 仪式(agent 主导"怎么下/怎么回")              │
│  · 观察常驻"[今天你能玩到 20:40(还剩35分钟)]"          │
│  · 到点前~10分钟:提醒"该收尾了"(卖垃圾/道别/托付)      │
│  · 告别词/理由完全由 agent 按人设即兴(已验证会演)       │
│  · 上线:观察给"你睡了一觉/上了天学,现在是…"衔接        │
└─────────────────────────────────────────────────────┘
```

**职责铁律**:下线/上线**时机归程序**(成本关键路径不许 agent 磨蹭),**方式归 agent**(怎么告别、编什么理由、要不要托付队友是演技问题)。对应 GPT 二轮"不追求刻意随机"原则:谁在线由持续状态(人设)决定,随机性只用于打破完全相同的时刻。

## 4. 时间模型

### 4.1 峰时日历(全局配置)

```json
"PeakGuard": {
  "Enabled": true,
  "Windows": [
    { "DaysOfWeek": "Mon-Fri", "UtcStart": "01:00", "UtcEnd": "04:00", "MaxOnline": 1, "Tag": "凌晨" },
    { "DaysOfWeek": "Mon-Fri", "UtcStart": "06:00", "UtcEnd": "10:00", "MaxOnline": 3, "Tag": "晚间" }
  ],
  "ChineseHolidays": ["2026-10-01", "2026-10-02", "2026-10-03", "..."],
  "PeakThinkIntervalMultiplier": 2.0,
  "LogoutGraceMinutes": 15
}
```

- 窗口存 UTC;换算用 `TimeZoneInfo("Central Standard Time")` 自动处理夏令时
- `MaxOnline` 按窗口分设(凌晨比晚间更狠)
- `ChineseHolidays` 手工维护(DeepSeek 按中国节假日放假,这天全天谷价)
- `PeakThinkIntervalMultiplier`:留守者思考间隔 ×2(峰时每一轮调用都是双倍价,少想多打——反射层照常,不损游戏行为)

### 4.2 人设作息(PersonaCard 扩展,v1.1:三态时刻表)

```json
"作息表": {
  "Active":  { "Weekday": ["15:00-19:30"], "Weekend": ["10:00-13:30", "19:30-23:30"] },
  "备注": "Active 之外、非峰时段 = AFK挂机;峰时 = 下线(除留守席)"
}
```

- 用**服务器本地时间**(bot 的世界时间=服务器时间,观察里已是本地钟)
- Active 窗口起止各 ±15 分钟高斯浮动,每日重摇(有人今天早退十分钟,明天赖五分钟)
- **谷时在线覆盖(v1.1 保证)**:非峰时段 12 人全员在线,只是 Active/AFK 比例随时段变化:

| 时段(CT,工作日) | 在线 | 其中 Active(键盘前) | 其中 AFK(挂机) | 电价 |
|---|---|---|---|---|
| 05:00-08:00 清晨 | 12 | 上班族 4(红缨/乱世佳人/白娘子/纵横四海) | 8 | 谷 |
| 08:00-12:00 上午 | 12 | 0~1(自由职业夜色无声偶尔在) | 11~12 | 谷 |
| 12:00-13:00 午休 | 12 | 上班族 4 | 8 | 谷 |
| 13:00-15:00 下午早段 | 12 | 0 | 12 | 谷 |
| 15:00-19:30 放学 | 12 | 学生党 3 + 机动档 3 | 6 | 谷 |
| 19:30-20:00 傍晚 | 12 | 机动档 3 | 9 | 谷 |
| **20:00-23:00 晚间峰** | **2-3** | 夜猫 2-3 | 0 | **峰×2** |
| 23:00-01:00 深夜谷 | 12 | 夜猫 2 + 晚睡的学生/上班族几个 | 其余 | 谷 |
| **01:00-05:00 凌晨峰** | **0-1** | 0-1 包夜党 | 0 | **峰×2** |

- v1.0 的空场窟窿(08:00-15:00 没人)被 AFK 填平:号挂着打怪,人"在上班/上学"——in-fiction 完全成立(2003 正是挂机外挂泛滥的年代)
- 周末全天谷价:全员在线,Active 窗口按周末表排,夜里人设该睡的转 AFK(通宵挂机)

## 5. 生命周期状态机(v1.1:三态)

```
                (人设作息窗口开始)                (峰时硬闸/作息远离线)
   AFK挂机 <────────────────> Active ───────> Closing ───────> Offline
   (号在线,反射挂机)  ──回归───  (键盘前)      (道别≤15min)
      │                                                  │
      │ (谷时全员可留 AFK;峰时硬闸点名 AFK 也下)          │ (峰窗结束/配额空位)
      └──────────────── Offline 回归见下 ────────────────┘
```

**Active → AFK(下班/上学/睡觉)**:
- 观察变化:"[你现在的状态] 挂机中(人在上班,晚上回来)" + 思考间隔×4~6 + 不主动说话
- 反射层照常:自动打怪/喝药/捡东西/挪窝(反射不花钱,这正是挂机的意义)
- SocialInbox 攒未读;死亡仍触发反思唤醒(号死了不管=掉装备,真人挂机也会看一眼)

**AFK → Active(下班回家/放学)**:
- 观察注入:"[你回来了] 你挂机这 4 小时:击杀 23 只/捡了 X/有人私聊你 3 条未读:…"
- agent 自然处理未读+汇报近况—— Continuity 得分点

**→ Closing → Offline(仅峰时硬闸或 GM)**:流程同 v1.0(§5.1):
1. 触发:峰窗进入时硬闸点名(夜猫分低者先下)/ GM 命令
2. Closing ≤15 分钟:道别+理由即兴(网吧关门/明天上学/没机时了…)、打完当前怪、托付、约明天
3. 宽限到期强下:Despawn + 退队 + 存档 + 记 LastLogoutAt/Reason

**Offline 回归**:同 v1.0 —— Spawn 到原位、[你刚上线] 衔接块(昨天几点/理由/未读承诺)、agent 自然打招呼。

**Offline 进入(下线流程)**:
1. 触发:作息窗口结束(浮动后) / 峰时硬闸点名 / GM 命令
2. `Closing` 态(最长 15 分钟宽限):
   - 观察插入:"[要下线了] 还有15分钟 —— 收个尾:手上怪打完、垃圾卖掉、跟队友/朋友说一声(用你的人设),有约定记 make_plan"
   - agent 自主收尾:道别语、理由(网吧关门/妈拔网线/明天上学/没机时了……由它即兴)、赠送托付、约明天
   - 组队中:打完当前战斗,队内说再见再走(宽限内)
3. 强制:宽限到期仍未走 → 服务器直接道别兜底(可选:无 say 则静默离线)+ Despawn
4. 落盘:位置/装备/金币/队伍脱离(自动退队)+ 存档(自动存档已每 5 分钟一次,退出时再触发一次)

**Offline 期间**:
- 零 LLM 调用、零反射;BotManager 不再 Process 该 bot
- 时间照走:承诺到期只记状态不发提醒(上线时补)
- **不伪造离线成长**:不涨经验不掉线死亡(GPT 二轮原则)

**Online 回归(上线流程)**:
1. 触发:作息窗口开始(浮动后);硬闸时期需配额空闲(排队逻辑见 §6.3)
2. Spawn 到下线位置(城里/安全区)
3. 观察注入衔接块:"[你刚上线] 你昨天/刚才 19:43 下线(理由:吃饭去了)。现在 X月X日 X点(周X)。你有 N 条未读:⏰该兑现的和水晶之恋组队(今天 17:00)/毒玫瑰给你留了句话"
4. agent 自然反应(已验证会演:"哈哈还没呢姐,我妈喊我写作业了"式回归、对过期承诺道歉补救)
5. `_conversation` 重开:[0]system + [1]记忆+昨日摘要 —— **每天的上下线天然替代了大部分压缩需求**(见 §10)

## 6. 留守者与配额

### 6.1 夜猫分(静态,人设属性)

PersonaCard 新增 `"夜猫倾向": 0.85`(0~1)。设计值:
- 夜色无声 0.9(独狼刺客,人设就是夜里出没,且**全天说话最少**——留守成本最低)
- 血饮狂刀 0.85(冲级狂,偶尔包夜)
- 毒玫瑰 0.5、赵子龙 0.4(好胜,熬夜要看心情)
- 其余 ≤0.2

### 6.2 晚间峰(20-23 CT)留守席

- 固定席:夜色无声、血饮狂刀(夜猫分 top2)
- 第 3 席(可选 P1):**真人检测**——若该窗口内有真人玩家在线,从机动档按夜猫分放行 1 人(陪玩优先);无真人则 2 人留守
- 留守者同样受 `PeakThinkIntervalMultiplier ×2` 节流

### 6.3 凌晨峰(01-05 CT)与排队

- 默认只允许夜猫分 ≥0.8 者且当日随机 1 人(或 0 人,可配);无人观看时段从紧
- 硬闸超员时下线顺序:夜猫分低者先下;同级则机动档先下
- 上线排队:硬闸期间想上线者进入 Pending,窗口结束/有空位按时间序放行(带 ±15min 浮动)

## 8. LLM 集成点(观察协议)

观察新增三个条件块(全部只 append,不动 system):

```
[你今天的作息] 现在在线到 19:43(还剩 31 分钟);明天 15:10 上线      ← 窗口内常驻
[要下线了] 还有 15 分钟 —— 收个尾:道别(用你的理由)、卖垃圾、有约定记 make_plan   ← Closing 态
[你刚上线] 昨晚 23:12 你说"网吧关门了"下线。现在是周四 15:11。你有 1 条该兑现的约定… ← 上线首轮
```

系统提示词追加一条(规则 15):
> "你有自己的生活节奏:观察里的 [你今天的作息] 是你的上下线时间,到点就该下线(道个别、说下理由,像真人)。别赖线,也别无声消失。"

工具集不变(不需要 logout 工具——**时机归程序**;若给 agent logout 权限会出现"为了省钱模型替程序做决定"的职责混乱,且不可控)。

## 9. 边界情况

| 情况 | 处理 |
|---|---|
| 服务器在峰时重启 | AutoStart 只拉起作息窗口内的 bot;硬闸窗口内只拉留守席 |
| Closing 中收到私聊 | 宽限内可回;已 Offline 则无响应(与真人一致),P2 做离线信箱 |
| 承诺兑现点落在离线期 | 上线时 [⏰该兑现了] + 过期时长;agent 自行道歉/改约(社交真实感反而加分) |
| 组队中到点 | 宽限 15 分钟:打完当前怪、队内道别、自动退队;到期强下 |
| 真人在峰时邀请留守 bot 组队 | 正常响应(留守的意义就是陪玩) |
| 人设窗口与硬闸同时到点 | 取更早者;下线理由由 agent 即兴(它不知道电价,只会说"网吧要关门了") |
| 节假日(中国) | 全天谷价:硬闸解除,作息表照常(周末窗口) |
| DST 切换日 | UTC 窗口换算自动偏移一小时,无人工干预 |

## 10. 顺带的架构收益(写给 review 者)

1. **上下文自然重置**:每天下线=会话丢弃,上线=[0]+[1]记忆重建。跨天本就不需要逐字记忆;这让 90% 压缩线更难触达,压缩全量 miss 的频率进一步下降。作息系统是"最拟人的成本优化"。
2. **观察日志降噪**:离线 bot 不产生无动作轮/堵死轮,JSONL 与 System.log 体量直接随在线数缩放。
3. **涌现连续性素材**:上线衔接块给了 agent "昨天"的锚点——"昨天说好带她打沃玛"这类跨日引用会自然增多,这正是 GPT 拟人度评测里 Continuity 维度的直接得分点。
4. **假下线彩蛋保留**:agent 仍可社交性假装下线("下了下了…再砍十分钟")——宽限期内这是合法的人味,系统不惩罚。

## 12. 给 GPT 的开放问题

1. 硬闸下线顺序用夜猫分排序,是否够?要不要叠加"最近一次在线时长"(连续在线久者先下,模拟疲劳)?
2. 晚间峰第 3 席的"真人检测放行"是否值得做?真人在线时间不可预测,可能长期空转一个席位的复杂度
3. 上线衔接观察里放多少离线期信息合适(目前:下线时间/理由/未读承诺 3 项)?会不会诱导 agent 每次上线都长篇"补作业"?
4. 作息浮动 ±15min 会不会让真人朋友觉得"约不准"(真人约"8点见"而 bot 7:52 就上线了)?是否需要对承诺时间点强制对齐浮动的例外?
5. 凌晨窗口完全清零 vs 留 1 人:留人有个半夜醒来看服务器的浪漫,清零多省 ~3% 成本——倾向哪个?
